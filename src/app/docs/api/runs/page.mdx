# Workflow runs

`POST /v1/runs` runs a Workflow app with the input variables you give it and returns the finished run — or streams progress as each step starts and completes. `POST /v1/runs/{run_id}/cancel` stops in-flight work, including chat replies.

## Run a workflow

<Endpoint method='POST' path='/v1/runs' />

Starts one run of the published workflow behind the API key. In blocking mode the call returns when the run has finished, with its outputs. In streaming mode you receive `run.started`, then a `step.started` and `step.completed` event for each block, then `run.completed` with the outputs.

**Supported app types:** <Tag tone='violet'>Workflow</Tag>

Conversational apps — including Agent Flow — are run through [chat completions](/docs/api/chat-completions), not this endpoint.

### Request body

<Params title='Request body'>
  <Param name='variables' type='object' required>
    Values for the workflow's input variables (the fields on its Trigger block), keyed by variable name. Send `{}` if the workflow has none. For a file variable pass an attachment object such as `{"type": "document", "url": "https://…"}`; for a file-list variable pass an array of them.
  </Param>
  <Param name='user' type='string' required>
    Your identifier for who started the run. Shown in the run logs.
  </Param>
  <Param name='stream' type='boolean' def='false'>
    `true` streams run and step events as Server-Sent Events.
  </Param>
  <Param name='attachments' type='array'>
    Files for the run, each `{"type": "image" | "document" | "audio" | "video", "url": "…"}` or with `file_id` instead of `url`. Same rules as [chat attachments](/docs/api/chat-completions#request-body).
  </Param>
</Params>

### Response

A blocking request returns a `run` object once the run has finished. A run that fails still returns `200` — check `status` and `error`.

<Params title='Run object'>
  <Param name='id' type='string'>The run id.</Param>
  <Param name='object' type='string'>`run` (or `run.completed` in a stream).</Param>
  <Param name='status' type='string'>`running`, `succeeded`, `failed`, `stopped` or `partial-succeeded` (the run finished, but a step failed and its error was handled).</Param>
  <Param name='variables' type='object | null'>Currently always `null` — the run's input values aren't echoed back.</Param>
  <Param name='outputs' type='object | null'>The workflow's outputs, keyed by the variable names of its **Output** block.</Param>
  <Param name='error' type='string | null'>Why the run failed, when `status` is `failed`.</Param>
  <Param name='steps' type='integer'>Number of steps executed.</Param>
  <Param name='tokens' type='integer'>Total tokens used by all model calls in the run.</Param>
  <Param name='elapsed_seconds' type='number'>Wall-clock duration of the run.</Param>
  <Param name='created_at' type='integer'>Unix timestamp when the run started.</Param>
  <Param name='finished_at' type='integer | null'>Unix timestamp when it finished.</Param>
</Params>

```json title="200 OK"
{
  "id": "7c1d9e3a-5b2f-4a8c-9e61-3f0a2b4c6d8e",
  "object": "run",
  "status": "succeeded",
  "variables": null,
  "outputs": { "summary": "Acme Ltd sells industrial fasteners…", "score": 82 },
  "error": null,
  "steps": 6,
  "tokens": 2143,
  "elapsed_seconds": 8.42,
  "created_at": 1759190400,
  "finished_at": 1759190408
}
```

<Tabs>
<Tab title='cURL'>

```bash title="Terminal"
curl https://cloud.xpectrum.dev/v1/runs \
  -H "Authorization: Bearer xpectrum_xxxxxxxxxxxx" \
  -H "Content-Type: application/json" \

    "variables": { "company": "Acme Ltd", "website": "https://acme.example" },
    "user": "crm-sync"
  }'
```

</Tab>
<Tab title='JavaScript (SDK)'>

```ts title="run.ts"
import { XpectrumWorkflow } from 'xpectrum'

const wf = new XpectrumWorkflow({
  baseUrl: 'https://cloud.xpectrum.dev/v1',
  apiKey: process.env.XPECTRUM_WORKFLOW_KEY!,
  user: 'crm-sync',
})

// Blocking
const run = await wf.run({ variables: { company: 'Acme Ltd', website: 'https://acme.example' } })
if (run.status !== 'succeeded') throw new Error(run.error ?? 'Run failed')
console.log(run.outputs)

// Streaming
await wf.stream({
  variables: { company: 'Acme Ltd' },
  onStart: (r) => console.log('run', r.id),
  onStepStart: (s) => console.log('→', s.title),
  onStepComplete: (s) => console.log('✓', s.title, s.status, s.elapsedSeconds),
  onDone: (r) => console.log(r.outputs),
})
```

</Tab>
<Tab title='Python'>

```python title="run.py"
import requests

resp = requests.post(
    "https://cloud.xpectrum.dev/v1/runs",
    headers={"Authorization": "Bearer xpectrum_xxxxxxxxxxxx"},
    json={
        "variables": {"company": "Acme Ltd", "website": "https://acme.example"},
        "user": "crm-sync",
    },
    timeout=300,
)
resp.raise_for_status()
run = resp.json()
if run["status"] != "succeeded":
    raise RuntimeError(run["error"])
print(run["outputs"])
```

## Streaming a run

With `"stream": true`, each event is a `data:` line with one JSON object. Keep-alive `: ping` comments arrive during long steps, and the stream ends with `data: [DONE]`.

```text title="Stream"
data: {"id":"7c1d…","object":"run.started","created_at":1759190400}

data: {"id":"a41f…","object":"step.started","title":"Fetch website","type":"http-request","index":2,"created_at":1759190400}

data: {"id":"a41f…","object":"step.completed","title":"Fetch website","type":"http-request","index":2,"created_at":1759190400,"status":"succeeded","outputs":{…},"error":null,"elapsed_seconds":1.12}

: ping

data: {"id":"7c1d…","object":"run.completed","status":"succeeded","variables":null,"outputs":{"summary":"…"},"error":null,"steps":6,"tokens":2143,"elapsed_seconds":8.42,"created_at":1759190400,"finished_at":1759190408}

data: [DONE]
```

| Event (`object`) | Fields | Meaning |
|---|---|---|
| `run.started` | `id`, `created_at` | The run was accepted. `id` is the run id. |
| `step.started` | `id`, `title`, `type`, `index`, `created_at` | A block started. `title` is the block's name on the canvas, `type` its kind, `index` its execution order. |
| `step.completed` | Same as `step.started`, plus `status`, `outputs`, `error`, `elapsed_seconds` | A block finished. |
| `run.completed` | The full [run object](#response) | The run finished — check `status`. |

Steps inside **For Each** and **Repeat Until** blocks are reported each time they run, and steps on parallel branches are reported as they start and finish. The **For Each** and **Repeat Until** blocks themselves, iteration progress, branch boundaries and retries are not sent as events. If the run fails to start or errors mid-stream, you receive `data: {"error": {"message": "…", "type": "server_error", "param": null, "code": "…"}}` followed by `[DONE]`. See [Streaming](/docs/api/streaming).

### Run limits

| Limit | Value | What you see |
|---|---|---|
| Steps per run | 500 | The run fails with `Max steps 500 reached.` |
| Run time | 1,200 seconds | The run fails with `Max execution time 1200s reached.` |
| Nested workflow calls | 5 levels | The run fails with `Max workflow call depth 5 reached.` |

For runs that may take more than a minute, stream them or trigger them from a [webhook](/docs/api/triggers-mcp) rather than holding a blocking request open. The SDK's blocking `wf.run()` gives up after 30 seconds, so use `wf.stream()` for anything longer.

### Errors

| Status | Type / code | Message | When |
|---|---|---|---|
| 400 | `invalid_param` (classic envelope) | `Arg user must be provided.` | `user` is missing or empty. |
| 400 | `invalid_param` (classic envelope) | Validation message, with `"params": "variables"` | `variables` is missing or not an object. |
| 400 | `invalid_request_error` | `'attachments' must be an array.` and the other [attachment messages](/docs/api/chat-completions#errors) | An attachment is malformed. |
| 400 | `invalid_request_error` | `Missing required variable 'X'.` | A required input variable is missing. |
| 400 | `invalid_request_error` | `Variable 'X' must be a number.` / `must be an attachment.` / `must be a list of attachments.` | A variable has the wrong type. |
| 400 | `invalid_request_error` | `This app has no published version yet.` | Publish the workflow first. |
| 400 | `invalid_request_error` / `model_not_supported` | `Model is currently not supported.` | A block's model can't be used. |
| 400 | `invalid_request_error` | `Invalid request.` | Any other invalid input. |
| 404 | `invalid_request_error` / `model_not_found` | `This API key belongs to an app that does not support runs (only workflow apps do).` | Use chat completions for conversational apps. |
| 429 | `rate_limit_exceeded` | Provider or plan message | Too many requests. Back off and retry. |
| 429 | `insufficient_quota` | `Model provider quota exceeded.` | The model provider's quota is used up. |
| 500 | `server_error` / `provider_not_initialized` | Provider message | A model provider has no valid credentials. |
| 500 | `server_error` | `Run failed.` or provider message | A model call failed. |
| 500 | `server_error` | `Internal server error.` | Unexpected failure. Retry. |

## Cancel a run

<Endpoint method='POST' path='/v1/runs/{run_id}/cancel' />

Tells the server to stop generating. Closing a stream or aborting a request on your side only stops you from **reading** the output — the model keeps generating and keeps using tokens until you call this endpoint. Use it for a **Stop** button in a chat UI.

**Supported app types:** <Tag tone='green'>AI Chatbot</Tag> <Tag tone='green'>Autonomous Agent</Tag> <Tag tone='green'>Agent Flow</Tag> <Tag tone='amber'>Multi-prompt Agent (Beta)</Tag> <Tag tone='violet'>Workflow</Tag>

<Params title='Path parameters'>
  <Param name='run_id' type='string' required>
    For a chat reply: the `run_id` from any chunk of a [chat completion stream](/docs/api/chat-completions#streaming-format). For a workflow: the run `id`.
  </Param>
</Params>

<Params title='Request body'>
  <Param name='user' type='string' required>
    The same `user` that started the reply or run. A different value does not stop it.
  </Param>
</Params>

### Response

<Params title='Response fields'>
  <Param name='id' type='string'>The `run_id` you sent.</Param>
  <Param name='object' type='string'>Always `run.cancelled`.</Param>
</Params>

```json title="200 OK"
{ "id": "e8b7f2a4-1c3d-4a5e-9b6f-7d8c9e0a1b2c", "object": "run.cancelled" }
```

The call is accepted even if the reply has already finished, the id is unknown, or `user` doesn't match — it never tells you whether something was actually stopped. After a successful stop, the open stream ends.

<Callout type='warning'>
  Cancellation currently stops **chat replies**. For runs started with `POST /runs`, the call is accepted but the run may continue to completion. Keep workflows within their [run limits](#run-limits), and avoid relying on cancel to stop side effects such as HTTP requests the workflow makes.
</Callout>
